## 01. 메모리 관리 최적화

대용량 처리 시스템에서 GC의 오버헤드는 일반적으로 시스템 응답 시간에 꼬리지연을 유발하는 요인이다. 힙 메모리 할당을 줄이는 것은 시스템 처리 성능을 향상시기키는 효과적인방법이다

* 주니어 방식
  * 빈번한 힙메모리 할당
    * new 키워드를 쉽게사용한다.
* 시니어 방식
  * 제로 할당 및 객체 풀 재사용
    * 호출 빈도가 높은 핫 패스에서 임시 배열과 객체를 할당하는것을 피한다.
    * 객체 풀을 통해 메모리를 재사용하고, 동기적으로 완료되는 경로에서는 `ValueTask`를 활용하여 최적화 한다.

```C#
    using System.Buffers;

    public readonly record struct SensorReading(int DeviceId, double Value);

    public class DataParser(ArrayPool<SensorReading> pool)
    {
        private readonly ArrayPool<SensorReading> _pool = pool;

        // ValueTask를 사용하여 Task 객체 할당을 줄이고, ReadOnlyMemory를 통해 복사를 방지함
        public async ValueTask<ReadOnlyMemory<SensorReading>> ParseOptimizedAsync(
            ReadOnlyMemory<byte> rawData, 
            CancellationToken ct = default)
        {
            // 객체 풀에서 버퍼를 대여하여 힙 영역에 새로운 배열이 할당되는 것을 방지
            var buffer = _pool.Rent(100);
            var count = 0;
  
            try
            {
                // 여기서는 복잡한 Span 분석 로직을 생략하고, 해석된 데이터를 버퍼에 직접 저장함
                buffer[count++] = new SensorReading(1, 45.2);
      
                // 비동기 대기를 시뮬레이션하지만, 동기적으로 완료될 경우 ValueTask 덕분에 힙 할당이 발생하지 않음
                await Task.Yield(); 
      
                return new ReadOnlyMemory<SensorReading>(buffer, 0, count);
            }
            catch
            {
                _pool.Return(buffer, clearArray: true);
                throw;
            }
        }
    }
```

`Task`를 `ValueTask`로 대체하고, `ArrayPool`을 사용하여 임시 배열을 재사용하면 고동시성 환경에서 GC 트리거 빈도를 줄이고 시스템 안정성을 강화할 수 있다.

## 02. 비동기 프로그래밍과 구조화된 동시성

비동기 프로그래밍은 단순히 `async`와 `await`를 나열하는데 그치지 않고, 동시실행 순서를 합리적으로 제어하고 스레드 컨텍스트를 적절하게 관리해야한다.

* 주니어 방식
  * 순차적 대기 및 불필요한 컨텍스트 캡처
    * 다중 비동기 작업을 처리시에 주로 루프내 순차 대기 방식을 사용하여 병렬로 실행 가능한 작업을 직렬로 실행해 효율성을 떨어트린다.
  * 시니어 방식
    * 병렬처리, 컨텍스트 무시 , c# 13 ref 로컬 변수
      * 병렬 태스크를 실행하고 `ConfigureAwait(false)`를 적절히 활용하여 컨텍스트를 해재한다.
      * ref 로컬변수를 조합하여 await 경계를 넘지 않는 범위에서 버퍼를 직접 수정한다

```C#
public async ValueTask<double[]> GetDevicesDataFastAsync(
    int[] deviceIds, 
    CancellationToken ct)
{
    if (deviceIds.Length == 0) return [];

    // 모든 비동기 작업을 병렬로 실행함
    var tasks = deviceIds
        .Select(id => FetchFromRemoteAsync(id, ct))
        .ToArray();

    // 라이브러리 및 비 UI 환경에서는 ConfigureAwait(false)를 통해 원래 동기화 컨텍스트로의 강제 복귀를 회피함
    var results = await Task.WhenAll(tasks).ConfigureAwait(false);
  
    // C# 13에서는 await 문을 가로지르지 않는 한 비동기 메서드 내에서 ref 로컬 변수를 선언할 수 있음
    ref double firstElement = ref results[0];
    if (firstElement < 0)
    {
        firstElement = 0.0; // 참조를 통해 직접 수정하여 메모리 주소 탐색 오버헤드를 배제함
    }

    return results;
}
```

## 03.현대적인 C# 13 구문 실무 적용

C# 13 은 컴파일러 수준의 여러 구문 설탕과 하위 레벨 최적화를 도입하였다. 이러한 신기능을 알맞게 사용하면 성능을 높게 유지하면서 한층 더 간결한 코드를 작성이 가능하다

* 주니어 방식
  * 번거로운 초기화 및 매개변수 변조 리스크
* 시니어 방식
  * 컬렉션 식, 기본생성자 읽기 전용 대입, field 키워드
    * C# 13에서는 컬렉션 식을 권장하고 기본 생성자 매겨변수를 읽기 전용 필드에 고정하여 추후 변조를 방지한다. 아울러 프리뷰 기능인 `field`키워드를 활용해 더욱 안전한 속성을 작성한다.

```C#
// 기본 생성자를 사용하고 이를 읽기 전용 멤버에 명시적으로 대입하여 추후 무단 수정을 방지함
public class UserConfigurationOptimized(string role)
{
    private readonly string _role = role;

    // C# 13의 컬렉션 식 사용; 컴파일러가 하부에서 배열 및 컬렉션의 생성 프로세스를 최적화함
    public ReadOnlySpan<string> DefaultPermissions => ["Read", "Write"];

    // C# 13의 field 키워드(프리뷰 기능)를 사용하여 자동 속성의 백업 필드에 직접 접근하므로 불필요한 상용구 작성을 예방함
    public required string SystemStatus
    {
        get => field;
        set
        {
            if (value is not ("Online" or "Offline")) 
                throw new ArgumentException("유효하지 않은 상태입니다");
            field = value;
        }
    }
}
```

## 04. 읽기 중심 및 쓰기 드문 시나리오의 극대화된 최적화 - FrozenCollections

수 많은 비지니스  시스템에서는 구동시에만 로드되고 실행 중에는 조회만 처리하는 대량의 정적 데이터가 존재한다.

* 주니어 방식
  * 표준 Dictionary 사용
    * 일반적인 해쉬는 데이터의 추가와 삭제 연산을 유연하게 지원하도록 설계되어 있어, 내부적으로 비교적 복잡한 충돌 해결 체인을 유지한다.
* 시니어 방식
  * FrozenDictionary 변환
    * Net 8.0 이상에서 이러한 정적 데이터에 대해 `System.Collections.Frozen`네임스페이스에서 제공하는 고정(Frozen) 컬렉션을 사용할 수 있다.

```C#
using System.Collections.Frozen;

private static readonly FrozenDictionary<int, string> _optimizedErrorCodes = 
    new Dictionary<int, string>
    {
        { 404, "리소스 없음" },
        { 500, "서버 내부 오류" }
    }.ToFrozenDictionary(); // 컴파일 또는 빌드 시점에 키를 충돌이 없는 해시맵으로 다시 매핑함
```

## 05. 하드웨어 가속 기반 문자/문자열 검색 - SearchValues

입력 텍스트를 대상으로 특정 문자나 민감한 금지 단어를 스캔하는 일은 대단히 흔한 비지니스 요구사항이다.

* 주니어 방식
  * 루프 매칭 또는 비효율적인 정규식
    * 특정 문자 그룹의 일치여부를 탐색하기 위해 LINQ나 정규식을 빈번히 호출하면 대량의 CPU 클록 사이클이 소모
* 시니어 방식
  * 컴파일 타임 하드웨어 가속 SearchValues 활용
    * Net 8에서 도입되고, Net 10에서 강화된 `SearchValues<T>`를 활용하면 검색 작업을 백터화 하여 하위 명령 세트에 위임이 가능하다

```C#
using System.Buffers;

public class SecurityValidator
{
    // 검색 값 세트를 미리 생성해 둠
    private static readonly SearchValues<char> _invalidPayload = 
        SearchValues.Create(['<', '>', '"', ''']);

    public bool HasInvalidSymbolsFast(ReadOnlySpan<char> text)
    {
        // 현재 CPU가 지원하는 최적의 명령 세트(AVX2, ARM NEON 등)를 자동으로 활용하여 초고속 스캔을 수행함
        return text.ContainsAny(_invalidPayload);
    }
}
```

`SearchValues`는 현재 실행 중인 장비의 CPU 아키텍처에 맞추어 최상의 병렬 컴퓨팅 방식을 동적으로 선정하고 극도로 빠르게 문자를 탐색한다. 이를 통해 직접 포인터를 제어하는 방식에서 발생할 수 있는 보안 위해 요소 역시 완벽 차단한다.

## 06.캐쉬 붕괴에 대응하는 공식 표준 방안 - HybridCache

동시 다발적인 대량의 요청이 한번에 만료된 캐시 영역을 돌파해 데이터베이스로 직접 쏟아질때(캐쉬 붕괴 현상) 시스템의 처리 부하가 급증하여 백엔드 전체가 일시 마비되는 사태가 초래될 수 있다.

* 주니어 방식
  * 더블 체크 잠금 및 수동 동시성 제어
    * 데이터베이스에 가해지는 동시 압박을 예방하기 위해 개발자가 직접 복잡한 락 로직을 작성하곤 하지만, 이는 데드락을 유발하기 쉽고 처리 허점이 남기 쉽다.
* 시니어 방식
  * Net 공식 내장 HybridCache 도입
    * 메모리 캐시(L1)와 분산 캐시(L2)를 완벽히 통합하며, 기본적으로 강력한 캐시 붕괴 방지 메커니즘을 지원

```C#
using Microsoft.Extensions.Caching.Hybrid;

public class CatalogService(HybridCache cache)
{
    private readonly HybridCache _cache = cache;

    public async ValueTask<string> GetCatalogDataOptimizedAsync(string key, CancellationToken ct)
    {
        // GetOrCreateAsync는 캐시 만료 시 오직 하나의 스레드만 하부 데이터베이스 쿼리를 처리하도록 전적으로 보장함
        return await _cache.GetOrCreateAsync(
            $"catalog:{key}",
            async token => await FetchFromDbAsync(key, token),
            cancellationToken: ct);
    }

    private Task<string> FetchFromDbAsync(string key, CancellationToken ct)
    {
        return Task.FromResult("데이터베이스 내 상품 정보 데이터");
    }
}
```

HybridCache의 고유한 보호 메커니즘은 중복 유입되는 쿼리를 자동으로 필터링합니다. 동시에 태그(Tag) 단위의 광범위한 연쇄 만료 기능을 지원해 복잡한 대규모 동기화 캐시 시스템을 손쉽게 조율할 수 있도록 돕는다.

## 07. 실행시간 리플렉션 대신 Source Generators 사용

행할 때 빠른 기동 속도와 낮은 메모리 점유율을 달성하기 위해 Native AOT 컴파일 배포가 핵심 주류로 정착하고 있다. 그러나 실행시간 리플렉션은 Native AOT환경과 호환되지 않으며, 실행 성능을 하락시키는 주요 요인이다.

* 주니어 방식
  * 리플렉션 기반 JSON 직렬화
    * 일반적인 개발 방식은 리플렉션 위주의 다양한 직렬화 라이브러리를 직접 호출한다. 이는 실행시간에 높은 오버헤드를 안길 뿐아니라 AOT 코드 트리밍 단계에서 필수 코드가 유실되는 오류를 유발한다.
* 시니어 방식
  * 컴파일 Source Generators 적용
    * `Source Generators`를 활용하면 컴파일러가 컴파일 빌드 단계에서 직렬화에 요구되는 메타데이터를 직접 완벽히 자동생성 하므로 런타임 리플렉션 아키텍처에도 조금도 빚지지 않게 된다.

```C#
using System.Text.Json.Serialization;

// 속성(Attribute) 지정을 통해 컴파일 타임에 직렬화 로직을 사전 빌드하도록 컴파일러에 명령함
[JsonSerializable(typeof(SensorReading))]
internal partial class SensorJsonContext : JsonSerializerContext
{
}

public class SerializerHelper
{
    public string SerializePayload(SensorReading reading)
    {
        // 컴파일 빌드된 컨텍스트 객체를 제공해 리플렉션 제로 직렬화를 완수하며 Native AOT와 완벽히 호환됨
        return JsonSerializer.Serialize(reading, SensorJsonContext.Default.SensorReading);
    }
}
```

고성능 처리 영역에서 소스생성 로깅 등과 같이 기타 빌드 생성 기법을 병행하면 애플리케이션의 최초 가동 속도를 획기적으로 향상시킬 수 있으며 실행시간 메모리를 최저 수즌으로 유지한다.

## 08.예외 및 오류 처리 시의 성능 관첨 고찰

C# 에서 예외를 인스턴스하고 Throw 하는 작업은 시스템의 호출 스택 (Stack Trace)정보를 가혹하게 수집하기 때문에 무거운 연사인다. 따라서 순수한 비지니스 제어 흐름 목적으로 예외를 결코 악용해서는 안 된다.

* 주니어 방식
  * 일반적인 데이터 검증에 예외 활용
    * 주니어 단계에서는 단순한 예외 입력 겁출 시 즉각 예외를 Throw 하여 제어흐름을 가로막는 흐름을 보인다.
* 시니어 방식
  * 결과 패턴 및 표준 문제 세부정보 활용
    * 보다 성숙한 설계는 비지니스 오류를 전용 `Result 패턴` 인스턴스로 전달하고 호출 클라이언트에 표준적인 Problem Details 형시긍로 반환하는 것을 제안한다.

```C#
// 레코드 형식을 활용해 가벼운 결과 전달 객체 정의
public abstract record OperationResult<T>
{
    public sealed record Success(T Data) : OperationResult<T>;
    public sealed record Failure(string ErrorCode, string Message) : OperationResult<T>;
}

public class BusinessCalculator
{
    public OperationResult<double> CalculateRateOptimized(double value)
    {
        if (value <= 0)
        {
            // 예외를 겪지 않는 일반 데이터로 결과를 전달하므로 호출 스택을 가혹하게 뒤지는 오버헤드가 없음
            return new OperationResult<double>.Failure("INVALID_VALUE", "계산값은 0 이하가 될 수 없습니다");
        }
        return new OperationResult<double>.Success(100.0 / value);
    }
}
```

API 인터페이스 계층에서 결과 매칭 식을 통해 `Failure` 전달상태를 응답 형식으로 매끄럽게 포맷 가공해 표준 오류레이아웃을 엄격하게 유지하면서도 트래픽이 집중되는 고성능 관문의 호출 품질을 영리하게 수호할 수 있다.

## 요약 : 시니어 개발자로의 지향점

진정한 프로덕션 급 고성능 소프트웨어를 제작하는 가치는 결국 코딩에 임하는 `마인드셋`의 점진적인 이동에 달려 있다.

* 운용 관점
  * 고동시성 상태에 놓인 시스템의 실제적인 동작 양상과 꼬리 품질 지연율에 날카롭게 시선을 고정
* 경제적인 관점
